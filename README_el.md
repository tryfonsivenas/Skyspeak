# SkySpeak

Οι μαθητές προγραμματίζουν ένα drone Tello γράφοντας ελληνικά ή αγγλικά. Ένα γλωσσικό μοντέλο (LLM) μετατρέπει την οδηγία σε πρόγραμμα από μπλοκ εντολών. Ο μαθητής βλέπει το πρόγραμμα και τη διαδρομή του (κάτοψη και πλάγια όψη) και πατά «Έγκριση και πτήση». Κάθε βήμα καταγράφεται για ερευνητική ανάλυση.

![προεπισκόπηση](docs/screenshot_preview.png)

## Γρήγορη εκκίνηση (προσομοίωση, χωρίς drone και χωρίς internet)

```
pip install fastapi uvicorn pyyaml httpx
./run.sh            (Windows: διπλό κλικ στο run.bat)
```
Μετά άνοιξε στον browser τη διεύθυνση **http://localhost:8000**.

Με τις αρχικές ρυθμίσεις, το `config.yaml` έχει `mode: sim` και `provider: mock`. Αυτό σημαίνει ότι δεν χρειάζεται ούτε drone ούτε κλειδί API· την οδηγία τη μετατρέπει ένας offline αναλυτής κανόνων, που καταλαβαίνει απλές φράσεις στα ελληνικά και τα αγγλικά (μπροστά/πίσω/πάνω, στροφές, τετράγωνο/τρίγωνο, φωτογραφία, «2 φορές»).

## Σύνδεση πραγματικού LLM

Στο `config.yaml`:

| provider | model (παράδειγμα) | api_key_env | Σημείωση |
|---|---|---|---|
| `openai` | `gpt-4o-mini` | `OPENAI_API_KEY` | |
| `anthropic` | `claude-sonnet-5-5` | `ANTHROPIC_API_KEY` | |
| `ollama` | `llama3.1:8b` | (κενό) | τρέχει τοπικά, δεν φεύγουν δεδομένα από το laptop |

Το κλειδί δεν γράφεται ποτέ στο αρχείο. Μπαίνει ως μεταβλητή περιβάλλοντος πριν την εκκίνηση:
`export OPENAI_API_KEY=sk-...` (Windows: `set OPENAI_API_KEY=sk-...`).

Τις οδηγίες που ακολουθεί το μοντέλο τις βρίσκεις στο `app/commands.py` (`SYSTEM_PROMPT`). Αν τις αλλάξεις, κατέγραψε την έκδοση για το paper.

## Πραγματική πτήση (Tello / Tello EDU / RoboMaster TT)

1. `pip install djitellopy opencv-python`
2. Ενεργοποίησε το Tello και σύνδεσε το laptop στο Wi-Fi του (`TELLO-XXXXXX`).
3. Στο `config.yaml` βάλε `mode: tello` και ξεκίνα όπως πριν. Η ένδειξη πάνω αριστερά γίνεται κόκκινη και γράφει «ΠΡΑΓΜΑΤΙΚΗ ΠΤΗΣΗ».

Ένα πρακτικό ζήτημα: όταν το laptop είναι συνδεδεμένο στο Wi-Fi του Tello, δεν έχει internet. Για OpenAI ή Anthropic χρειάζεσαι δεύτερη σύνδεση (ethernet ή USB Wi-Fi dongle). Οι άλλες λύσεις είναι το Tello EDU σε station mode, που συνδέεται στο router της τάξης, ή το `ollama` / `mock`, που δουλεύουν χωρίς internet.

## Ασφάλεια (`config.yaml` → `safety`)

Κάθε πρόγραμμα ελέγχεται στον server πριν πετάξει, ακόμα κι αν κάποιος αλλάξει τον browser:

- Επιτρέπονται μόνο εντολές από λίστα (whitelist) και κάθε τιμή πρέπει να είναι μέσα στα όρια του Tello SDK.
- Υπάρχει μέγιστο ύψος (200 εκ.) και νοητός φράχτης (geofence) 3 μέτρων γύρω από το σημείο απογείωσης. Το drone δεν επιτρέπεται να κατέβει κάτω από 20 εκ. όσο πετάει.
- Ένα πρόγραμμα έχει το πολύ 20 εντολές. Η απογείωση και η προσγείωση προστίθενται αυτόματα αν λείπουν.
- Το drone δεν πετά αν η μπαταρία είναι κάτω από 25%.
- Τίποτα δεν εκτελείται χωρίς ρητή έγκριση από τον μαθητή.
- Το κόκκινο κουμπί «ΕΚΤΑΚΤΗ ΠΡΟΣΓΕΙΩΣΗ» σταματά το πρόγραμμα και προσγειώνει το drone. Αν η προσγείωση αποτύχει, κόβει τους κινητήρες.

Το λογισμικό δεν αντικαθιστά την επίβλεψη από ενήλικα. Πέτα σε κλειστό χώρο, με τα προστατευτικά των ελίκων, και κράτα τους μαθητές πίσω από μια γραμμή στο πάτωμα.

## Ερευνητικά δεδομένα

Σε κάθε εκκίνηση δημιουργείται ένα αρχείο `logs/session_<ημερομηνία>_<id>.jsonl` με ένα γεγονός ανά γραμμή:

| event | Περιεχόμενο |
|---|---|
| `generate` | κωδικός μαθητή, η οδηγία, πάροχος/μοντέλο, χρόνος απόκρισης, η **ακατέργαστη** έξοδος του LLM, το επικυρωμένο πρόγραμμα, τα σφάλματα και οι προειδοποιήσεις |
| `approve` | το πρόγραμμα που ενέκρινε ο μαθητής (ίσως αφού αφαίρεσε μπλοκ) |
| `command_done` | κάθε εντολή, η διάρκειά της, η μπαταρία και το ύψος |
| `execute_end`, `execute_error`, `emergency` | πώς τελείωσε η πτήση |
| `note` | η αξιολόγηση του μαθητή (👍/🤏/👎) |

Από αυτά τα δεδομένα μπορείς να βγάλεις για το paper:
- το ποσοστό των οδηγιών που μετατράπηκαν σε έγκυρο πρόγραμμα·
- πόσες προσπάθειες χρειάστηκαν μέχρι να επιτευχθεί ο στόχος·
- τους τύπους λαθών·
- τη σύγκριση μεταξύ των μοντέλων.

Ο κωδικός μαθητή δέχεται μόνο λατινικούς χαρακτήρες, αριθμούς, `-` και `_` (π.χ. `S01`), ώστε να μην καταγράφονται ονόματα. Μην ζητάς ονόματα από τα παιδιά.

Για τη σύγκριση με blocks: στο φυσικό σκέλος της μελέτης μπορείς να χρησιμοποιήσεις την ίδια εφαρμογή με τα ίδια όρια ασφαλείας. Στην ομάδα ελέγχου, ο μαθητής δουλεύει με Tello EDU app ή DroneBlocks.


## Γνωστοί περιορισμοί

- Ο offline αναλυτής είναι απλός. Για την πραγματική μελέτη χρησιμοποίησε LLM και κράτα το `mock` ως εφεδρεία ή ως συνθήκη baseline.
- Η διαδρομή στην οθόνη είναι ιδανική. Το Tello μετατοπίζεται λίγο, ειδικά σε γυαλιστερά δάπεδα με λίγο φως.
- Ο κύκλος προσεγγίζεται με εξάγωνο. Οι εντολές `curve` και `flip` δεν περιλαμβάνονται σκόπιμα.
- Υποστηρίζεται ένα drone τη φορά. Η λειτουργία σμήνους για Tello EDU είναι πιθανή επέκταση.

## Τεχνική αξιολόγηση και πτήσεις (για το paper)

Οδηγίες βήμα προς βήμα: `eval/Odigies_texnikis_axiologisis.docx` και `eval/Odigies_ptiseon_Tello.docx`.

Στα Windows ο πιο απλός τρόπος είναι διπλό κλικ στο `run_evaluation_windows.bat`: ρωτά τα κλειδιά, κάνει γρήγορη δοκιμή, τρέχει όλα τα μοντέλα (cloud και τοπικά μέσω Ollama), βγάζει πίνακες και γράφημα και φτιάχνει το `results_for_paper.zip`.

```
python -m eval.run_eval --provider mock                      # βάση σύγκρισης (έχει ήδη τρέξει)
python -m eval.run_eval --provider openai --model gpt-4o-mini --api-key-env OPENAI_API_KEY
python -m eval.summarize                                      # πίνακες στο eval/results
python -m eval.plot_results                                   # Σχήμα 4 στο paper/fig
python -m eval.flight_trial                                   # 20 πραγματικές πτήσεις με το Tello
```

Το σύνολο δοκιμής (`eval/testset.json`, 80 οδηγίες) και το `SYSTEM_PROMPT` δεν αλλάζουν μετά την έναρξη των μετρήσεων.
